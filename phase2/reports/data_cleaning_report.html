1. Executive Summary

This report documents the end-to-end data cleansing, standardization, and transformation pipeline developed for The Boot Room data warehouse. Raw event streams, match sheets, team metadata, and player lineups pulled directly from the public StatsBomb Open Data repository are systematically scrubbed and conformed.

The ETL architecture utilizes an ELT (Extract-Load-Transform) philosophy: raw dirty strings are first ingested into dedicated staging tables (project_staging) to ensure complete auditability, and then transformed during the dimensional and fact loading stages into the conformed star schema (project_dw).

2. Source Data Profile & Identified Inconsistencies

Open sports event data exhibits several common anomalies across match sheets, player registries, and pitch tracking coordinates:

  • Whitespace and Capitalization Variances: Inconsistent padding, mixed case strings, and disparate naming conventions across different competitions (e.g., " FC BARCELONA ", "barcelona").
  • Sparse Attributes & Null Representations: Missing player nicknames, unspecified referee details, or empty string representations ("" vs NULL) in lineup positions.
  • Substitutions and Position Shifts: Bench substitutes lacking starting pitch coordinates or assigned tactical positions in raw match sheets.
  • Data Type Coercion Challenges: Dates, kick-off timestamps, and xG expected goals delivered as variable string formats requiring strict casting to PostgreSQL DATE, TIME, and NUMERIC(6,3).

4. Surrogate Key Architecture & Mapping

In compliance with Kimball data warehousing standards, all operational/natural keys (e.g. player_id = 5503, team_id = 217) are separated from the internal surrogate keys (e.g. player_key = 1042, team_key = 102).

-- Surrogate Key Pipeline Example (04_load_dimensions.sql & 05_load_facts.sql) -- 1. Dimension Load generates serial integer primary keys: INSERT INTO project_dw.dim_player (player_id, player_name, nationality, primary_position) SELECT DISTINCT ON (CAST(player_id AS INTEGER)) CAST(player_id AS INTEGER), INITCAP(TRIM(player_name)), INITCAP(TRIM(NULLIF(nationality, ''))), INITCAP(TRIM(NULLIF(position, ''))) FROM project_staging.stg_player ORDER BY CAST(player_id AS INTEGER); -- 2. Fact Load resolves business key to surrogate key: INSERT INTO project_dw.fact_player_match (player_key, match_key, team_key, ...) SELECT dp.player_key, -- Conformed Surrogate Key from dim_player dm.match_key, -- Conformed Surrogate Key from dim_match dt.team_key, -- Conformed Surrogate Key from dim_team ... FROM project_staging.stg_player_match_summary spm JOIN project_dw.dim_player dp ON dp.player_id = CAST(spm.player_id AS INTEGER) JOIN project_dw.dim_match dm ON dm.match_id = CAST(spm.match_id AS INTEGER) JOIN project_dw.dim_team dt ON dt.team_id = CAST(spm.team_id AS INTEGER);

6. Conclusion

The cleansing pipeline successfully transforms untamed, high-velocity open event data into pristine, normalized star schema dimensions and fact tables. All surrogate key mappings operate with strict referential integrity, eliminating duplicates and formatting anomalies while retaining full provenance back to source match IDs.
